# DOS, CPU, memory, and drivers

`shizukudos/` is a newly written boot environment with FAT12, limited COM execution, PCI read-only probing, and chainload tests. It is the intended FreeDOS replacement, but does not yet replace Windows 98 `IO.SYS` or boot the GUI. Keep its test disks separate from installed guest disks. Preserve the Win98 boot and DOS interrupt contracts when extending it. DOS changes alone cannot give the Win98 GUI symmetric multiprocessing; the multicore goal also needs VMM and scheduler work. Count it as supported only after the installed Win98 guest boots, reports usable processors, and runs independent CPU-bound processes concurrently on distinct guest processors.

`cpu/` currently chooses app profiles and launches processes. Per-app i386/i486/Pentium MMX/II/III/Modern ISA and speed enforcement needs an actual execution-interposition, binary translation, or virtualization mechanism; changing a label or CPUID report alone is insufficient. VT-x/AMD-V acceleration is mandatory for the project's supported test path. Verify it from a live VM log, not just a configuration flag.

`memory/` contains bounded virtual-page tests. The VM's PAE flag, CPUID PAE bit, E820 map, `GlobalMemoryStatus`, guest CR4.PAE/page-table mode, and genuinely usable guest physical pages are separate measurements. The updated requirement is **real PAE support and access to all usable RAM on the targeted modern CSM system**, including RAM above 4 GiB. A `MaxPhysPage` cap, successful large virtual allocation, or configured VM RAM is not proof. Test disposable clones in increasing RAM steps above 4 GiB; preserve base-disk hashes and capture normal boot, physical memory mapping, stress across low and high pages with concurrent workers, reboot, and clean shutdown. Compare accessible physical pages against the firmware's usable E820 map while accounting for reserved regions and the PCI/MMIO hole. Each 32-bit process retains its own virtual address limits. A real solution requires Win9x VMM/page-table and cache/MMIO changes; report a verified capacity for each tested machine instead of generalizing from one VM size.

`drivers/` presently contains plans and safe read-only AHCI/xHCI parsing, not working drivers. The hardware target is a modern machine that can boot through CSM, with Skylake-class SATA/AHCI and xHCI as minimum preparation. Treat AHCI and xHCI as distinct Win9x driver projects with DMA/interrupt/resource-management requirements. With no matching physical PC available, report VM and hardware evidence separately and do not claim hardware support from a probe alone.
